# 线索数据处理工具

纯前端（浏览器端）线索数据处理工具，可在本地直接打开，也可部署到 GitHub Pages 通过网址访问。

## 功能

- 导入：点击或拖拽上传「CRM-水师营-线上表」结构的 .xlsx 文件（需包含工作表：CRM、水师营、线上表、人员名单、配对过程、意向明细）
- 处理：点击「开始处理」，按既定规则自动完成结果1、结果2、意向明细、人员名单完成量/完成率
- 输出：
  - **处理后的 Excel**（含 结果1、结果2、意向明细、人员名单 等）
  - **可视化分析报告**（.html，内嵌预览 + 可下载），框架含 KPI 卡片、线索量 TOP8 条形图、平台来源环形图、人员明细/地市汇总/岗位汇总/平台分布/明细数据

## 处理规则（已定稿）

1. **结果1（配对过程 A–E）**：CRM「手机号码密文」∩ 水师营「学员手机」**纯手机号匹配**（不做时间过滤）。A=学员手机；B/C/D=该手机去重「录入人姓名」（最多3个）；E=CRM「活动名称」。
2. **结果2（配对过程 F–K）**：结果1 与 线上表 的**并集，交集只列一次**。线上表「线索号码」脱敏（前3位+`****`+第8位起）；空白号码→`****`；非电话数据按同规则脱敏。
   - F=线索、G=线索归属人（水师营仅取录入人；交集/线上表仅取账号运营人）、J=CRM活动（线上表仅为空）、K=平台来源（空则补「小红书」）。
3. **意向明细**：线索=F；线索归属人=G；分校/岗位=按归属人匹配人员名单（未匹配留空）；统计来源=仅水师营→「水师营」、仅线上表→「线上表格」、交集→「水师营/线上表格」；平台来源=K。多录入人按行展开。
4. **人员名单**：完成量=该姓名在意向明细作为线索归属人的条数；完成率=完成量/意向目标（显示为百分比）。

## 本地预览

```bash
python -m http.server 8000 --directory <本目录>
# 浏览器打开 http://localhost:8000
```

或直接双击 `index.html`（需联网加载 CDN）。

## 部署到 GitHub Pages

1. 在 GitHub 新建公开仓库（如 `Intentional-Clue-Analysis`）。
2. 将 `index.html`、`logic.js`、`README.md` 上传到仓库 main 分支。
3. 仓库 Settings → Pages → Source 选择「Deploy from a branch」→ 分支选 `main`、目录 `/ (root)` → Save。
4. 等待 1-2 分钟，访问 `https://<你的用户名>.github.io/<仓库名>/`。

## 文件说明

- `index.html`：页面（上传/处理/下载/报告预览/规则说明）
- `logic.js`：核心处理逻辑（UMD，浏览器与 Node 通用）
- `validate.js`：Node 校验脚本（`node validate.js <输入xlsx>`）
- `README.md`：本说明
